Mail on your own domains.

mail for your domains

People read and send mail in the browser, at addresses on your domains. Your projects send their own mail, such as sign-in links, through an API key. It is one Cloudflare Worker, with no mail server to keep patched.

why

Your own addresses, without a mail server.

Mail on your own domains usually means a mail server to keep patched, or a hosted provider that holds every message. cfx-mail is one Cloudflare Worker with a D1 database and an R2 bucket. Cloudflare Email Routing brings mail in, and Email Sending takes it out. The people you invite read their mail in the browser, and your projects send their sign-in links and alerts through the same deployment.

what it does

  • personal, group, temporary and service mailboxes
  • several domains, one sign-in, one inbox
  • conversations, search, labels, folders and rules
  • reminders, scheduled sending and push notifications
  • sender checks, spam scoring and blocklists
  • remote images through the Worker, tracking pixels removed
  • one-click unsubscribe, both ways
  • aliases and catch-alls, across domains

how

Invite people, then let your projects send

  1. 1

    Invite people, and give them mailboxes

    An admin invites each person. A personal mailbox belongs to one person, a group mailbox is shared with read, write or manage rights, a temporary address deletes itself, and a service mailbox is for a project’s code.

  2. 2

    Mail arrives, and is checked on the way in

    Cloudflare Email Routing hands each message to the Worker. It checks the sender with SPF, DKIM and DMARC, scores it for spam, and checks public blocklists and one of your own, before the mail lands in its mailbox.

  3. 3

    Read and write in the browser

    One sign-in reaches every mailbox a person has, across domains, with an inbox that shows them all. Remote images load through the Worker, tracking pixels are removed, and location data is stripped from attached photos.

  4. 4

    Let a project send its own mail

    A project sends with one request and its service mailbox’s key. The mail goes out from that mailbox’s address, and a copy is kept in it:

    curl -sS -X POST "https://mail.example.com/api/svc/send" \
  -H "Authorization: Bearer $CFMAIL_KEY" \
  -H "Content-Type: application/json" \
  -d '{"to": [{"address": "person@example.org"}],
       "subject": "Your sign-in link",
       "text": "Open https://app.example.org/magic?token=abc"}'
# 201 {"messageId":"…","threadId":"…"}
  5. 5

    Keep a copy at home

    Backups go to a folder on your own machine, and can be restored from it.

what it doesn’t do

  • mail appsIMAP is built, but Cloudflare cannot expose it to the internet yet, so it is switched off.
  • encryptionPGP is built and switched off.
  • attachments by APIThe send API takes text and HTML, and no attachments.
  • sign-upNobody can sign up. An admin invites each person.
  • admin passwordsAdmins sign in only with a Cloudflare login that is a member of the deployment’s account.

install

Install

You need a Cloudflare account on the Workers Paid plan, which starts at $5 a month, and a domain on Cloudflare with Email Routing and Email Sending turned on. Get the code, create a D1 database and an R2 bucket, write your values into a private site file, set three Worker secrets, then deploy:

git clone https://github.com/c-f-x/cfx-mail
cd cfx-mail
CFX_SITE=~/my-site npx -y pnpm@12.4.1 run deploy <name>

The deploy builds the app, applies the database migrations and deploys the Worker. Every step, written so a coding agent can follow it and so can you, is in AGENTS.md, section 4.
